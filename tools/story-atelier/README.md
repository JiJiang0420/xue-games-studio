> 本目录用于源码维护，保存在 `xue-games-studio` 仓库的 `story-atelier` 分支、`tools/story-atelier/` 路径。

## 个人本地版：使用自己的 ChatGPT 套餐

[下载 V1.4.1 个人本地包](offline/Story_Atelier_Personal_V1.4.1.zip)，完整解压。Windows 安装 [Node.js 24 LTS 或更新的 LTS 版本](https://nodejs.org/en/download)后，双击 **启动叙事工坊.cmd**。浏览器打开 `http://127.0.0.1:4178/`，进入「连接 ChatGPT Plus」→「使用 ChatGPT 继续」，在 OpenAI 官方页登录并允许使用套餐，然后用设置里的示例实测确认生成成功。

个人入口默认选择 ChatGPT 套餐，不读取 API 密钥，也不提供 API 计费切换。macOS 使用 `Start_Personal_Writer.command`，Linux 运行 `node start-personal.mjs`。工作台仅在本机监听，作品保存在当前浏览器；使用 ChatGPT 生成时仍需联网，相关手稿和设定会发送给 OpenAI。真实使用资格、模型与限额以授权账号为准。

在线版旧作可先导出「完整备份 JSON」，再在本地「设置与备份」导入。固定使用同一浏览器和地址，定期备份。详见包内「先读我_个人版使用说明.txt」。本包无需安装项目依赖或本地模型。

开发者打包：先运行 `node studio/build.mjs`，再运行 `python3 scripts/package-personal.py`。打包脚本采用明确文件清单，不包含授权文件、环境配置或用户作品。

## 用 ChatGPT Plus 续写

[下载 V1.4 工具包](offline/Story_Atelier_V1.4.zip)并解压到电脑。安装 Node.js 22.13 或更新版本。Windows 双击 `Start_Local_Writer.cmd`，macOS 双击 `Start_Local_Writer.command`，Linux 可在解压目录运行 `node local-writer.mjs --open`。

1. 在工坊首页点「连接 ChatGPT Plus」，或者进入「设置与备份」。点「使用 ChatGPT 继续」。
2. 在 OpenAI 的授权页选择你的 Plus 账号和工作区，允许 **Use your ChatGPT plan**。页面会回到本机工坊。套餐模型菜单会显示这个账号可以选用的模型。
3. 点「用示例实测 OpenAI」。出现一段续写后，回首页贴入手稿，点「接着原文写」。模型结果先作为候选，点「接入正文」才会追加到手稿。

大纲、续写、连续性审阅和「创作知识库」中的联网研究共用所选连接。联网研究需要账号和模型支持网页搜索。设置中可查看当前账号、切换套餐模型、断开连接或[查看 ChatGPT 用量](https://chatgpt.com/settings/usage)。达到套餐限额会暂停请求。单独使用项目 API 密钥要在设置里明确选择该方式。

浏览器和本机启动器须运行在同一台电脑。通过 OpenAI 官方授权页登录，授权回调返回本机。启动器在个人配置目录的 `glhf-story-atelier/chatgpt.sqlite` 中保存套餐授权。浏览器中的作品、导出的备份与分发包都独立于这份凭据。直接打开 HTML 可使用离线规则起草。

[OpenAI 官方套餐授权说明](https://developers.openai.com/siwc/token-sharing-open-source) · [可用模型和响应流](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)

## 用项目 API 密钥创作

使用 API 计费的作者可在启动器所在电脑配置 `OPENAI_API_KEY`，或从同目录的 `.env.local` 读取。源码启动时也会读取工具项目根目录的 `.env.local`。已选套餐时，需在「设置与备份」点「改用项目 API 密钥」才会切换计费方式。

用项目密钥时，设置页显示「已读取密钥」。基础模型为 `gpt-5.4-mini`，可填写项目允许的模型 ID。「用示例实测 OpenAI」会发出一次真实模型请求。API 组织余额不足时，界面会显示具体原因和账单入口。[OpenAI 用量与额度说明](https://help.openai.com/en/articles/6614457-troubleshooting-api-usage-and-spend-limits)

## 从你写的内容开始

解压工具包，通过本机启动器或 `Story_Atelier_Offline.html` 打开工作台。

- 一句创意：在首页输入「顾禾收到一张从明天寄来的明信片」，点「写成开头」。这一句会保存在作品设定里。
- 一段原文：贴上手稿，点「接着原文写」。也可以打开已有章节，在正文下方点「写下一段」。可以选择顺势推进、用对话推进或加入转折。
- 新段落出现在候选框。可以逐字改、换一种写法或舍弃。点「接入正文」才会追加，原有文字、事实记录和分支选择都会保留。改动手稿或相关设定后，工具会要求基于新内容重新生成。
- 离线规则草稿直接使用浏览器里的组句规则。它能围绕人名、物件、问句和部分情节起草短段落，同一场景可用的变化有限。长篇或自由题材可以使用本机对话模型。

### 启用本机模型

在电脑上安装 Node.js 22.13 或更新版本及 Ollama，在 Ollama 中下载并运行一个支持中文创作的**本地对话模型**。解压目录中，Windows 双击 `Start_Local_Writer.cmd`，macOS 双击 `Start_Local_Writer.command`。也可在同一目录的终端运行：

```sh
node local-writer.mjs --open
```

浏览器会打开 `http://127.0.0.1:4178/`。如果只配置了 Ollama，首次检测到本地模型时，工作台会默认选中第一个。若同时配置了 OpenAI，则优先使用 OpenAI。可在「创作方式」更换。若上次手动选过规则草稿，重新选定模型即可。模型服务启动较晚，可在章节里点「重新检测模型」。保持启动器窗口打开，结束时按 Ctrl+C。启动器只在本机回环地址监听，模型权重由 Ollama 管理。

模型会接收当前稿件、作品设定、绑定的人物与场景、匹配的资料片段和当前章的共同来路。长章保留开头及最近约 6,800 个字符。有循环的互动故事使用当前章原文和事实记录。已配置的 OpenAI 服务也可在「创作方式」里手动选择。离线文件和本机 HTTP 地址各有独立的浏览器存储，迁移旧作请使用完整备份。

Ollama 接口文档见[本机对话](https://docs.ollama.com/api/chat)和[模型清单](https://docs.ollama.com/api/tags)。

## 用一个故事试一下线索分支

打开工作台，点击首页的「试读《失物招领处》」。

- 先走「先到窗口接待她」。核对存根的选项会显示缺少的线索，仍可开待领单并读到「明早八点」。
- 点「从头试读」，走「先翻交接簿」→「带上蓝色存根，回到窗口」。此时可以核对存根、交还磁带，读到「三下跺脚」。点「返回上一节点」，刚交出的存根会回到手里。
- 点试读页的「编辑此稿」→「本作线索」可创建或改名线索，或勾选「开局持有」。在章节正文下方展开选项的「线索规则」，设置选择前需持有或未持有的线索，以及选择后获得或交出的线索。每个选项可带一个条件、一个结果，均可留空。
- 「本地发布」会检查可到达的章节、选项和结局，并指出具体哪种持有状态会卡住。检查达到 4,096 种状态时会提示还有路线待试读。读者回退时会恢复当时的线索状态。

工具包附有[示例项目 JSON](examples/story/Clue_Counter.json)和[独立阅读页](examples/story/Clue_Counter_Reader.html)。V1.0 项目与备份可以从「设置与备份」导入。若要在新下载的文件中继续旧作，先在旧版导出完整备份，再在新版导入。

## 使用顺序

1. 点“开始新故事”，填写名称、创意、剧情类型、文学风格、标签、篇幅和章节数。
2. 需要时先在“角色与场景”建立人物动机、关系、成长弧线、场景感官与冲突，并在剧情集“设定”中绑定。
3. 在“创作知识库”查找内置方法卡、导入 TXT/MD 笔记，或点击“联网研究”按主题查找参考资料。联网研究显示可点击来源，保存后再绑定到作品。
4. 进入章节编辑，点“规划大纲”。检查大纲和分支后点“按大纲逐章生成”。也可以完全手写，或导入 Markdown/JSON 正文。
5. 检查正文与事实记录，使用“检查连续性”获得修改建议。审阅不会自动改稿。
6. 打开“试读”，走通选项；在“本地发布”窗口保存独立快照，再从书架导出 HTML 阅读页。
7. 定期点右上角“备份”，保存完整 JSON。

## 数据、范围与边界

- 作品、设定、资料和发布版保存在当前浏览器 IndexedDB。不同设备、不同域名和离线文件的数据不会自动同步；用完整备份 JSON 迁移。
- 本地发布只在当前浏览器保存。在线工具本身的访问权限与作品发布是两回事。分享导出的阅读 HTML 才会把作品交给别人。
- OpenAI 创作任务把当前设定、绑定人物场景、相关资料片段及必要上下文发送到 OpenAI。联网研究只发送研究框里的主题。服务端请求使用 `store:false`。
- 知识库是可扩充的摘要与检索系统，并未收录“全部人类知识”或所有书籍，也没有重新训练模型；资料事实需自行核对。只导入自有、获授权或适用的公版内容。
- 规模范围：500–300,000 个非空白字符、1–100 章；AI 每章目标 200–8,000 字符。单次输出有偏差，完成后显示实际总量。大任务需要保持页面打开；到预算上限可再次续写。
- 为防止互斥分支混淆，自动生成按照无环分支图排序，并仅使用所有入站路径共有的前驱事实。每次选择维护独立的线索持有状态。当前支持持有与未持有判定，线索规则会随章节设定一并传入创作上下文。
- 手动修改正文后，系统清除该章自动续写标记和旧事实摘要；请更新事实记录。批量逐章生成跳过手工正文。用「写下一段」可在保留手稿和现有事实记录的前提下继续创作。
- 每章生成最多 8 段后暂停，未达到目标会明确提示续写。长篇连续性仍需要作者审阅；单次审阅文本每章最多 7,000 字符。
- TXT/MD 单个导入限制 1 MB；全文读取以文本格式为主，不直接解析 PDF/EPUB。

## 离线编辑版

本目录内的 `offline/Story_Atelier_Offline.html` 是自包含页面，解压后用 Chrome/Edge 打开。它支持离线规则起草、编辑、资料库、本地保存、阅读和导出。使用 OpenAI 或本地对话模型时，请通过本机启动器打开工作台。

若浏览器禁用 file:// 下的存储，页面会显示保存异常；应先导出备份，并改用离线包附带的本机 HTTP 启动器。

## 源码与开发

- `studio/`：前端源文件、知识卡、打包脚本。
- `public/studio.html`：自包含编辑工作台，由 `node studio/build.mjs` 生成。
- `offline/openai-agent.mjs` 被本机启动器与服务端共用，负责调用 OpenAI、解析结构化结果与分类模型服务错误。
- `app/api/agent/route.ts` 负责服务端身份与来源检查。
- `app/page.tsx`、`app/layout.tsx`：在线工作台容器。
- `tests/`：Node 测试。`node --test tests/*.test.mjs`。
- `studio/knowledge_sources.json`：18 条可核查来源与原创摘要。

在线版基于 Sites Vinext / Cloudflare Workers。开发环境要求 Node 22.13+，使用 package.json 指定的 pnpm。安装依赖后运行 `node studio/build.mjs`、`pnpm dev`；正式构建遵循 Sites 的构建与发布流程。不要把 `.env`、`.dev.vars` 或密钥提交到代码仓库。
