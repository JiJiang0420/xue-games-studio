策划与设计01 / 20

MDA 游戏设计框架

从机制、动态与体验三个层次分析游戏，帮助把体验目标转化为可验证的设计。

希望梳理玩法方向与核心循环的策划或独立开发者。

阅读学习指南 ＋

建议学习顺序

  1. 阅读原文，区分 Mechanics、Dynamics、Aesthetics
  2. 选一款熟悉的游戏，描述规则、玩家行为和体验
  3. 为自己的原型确定一个主要体验目标
  4. 从目标反推规则，并预测可能的玩家行为

动手练习

写一页核心玩法说明：目标玩家、主要体验、30 秒核心循环、规则与一个待验证假设。

完成标准

明确区分规则和实际行为；列出至少一个可能违背预期的行为，并设计试玩观察方法。

注意事项

原文为英文论文；框架用于提出和讨论假设，不能替代实际试玩。

建议将实践步骤、使用版本与实际结果记录为学习笔记。以上练习均待实践。

策划与设计02 / 20

The Level Design Book

关卡设计开放教材，覆盖空间、流程、白盒原型与迭代。

需要把玩法放进可探索、可理解的关卡。

阅读学习指南 ＋

建议学习顺序

  1. 先读关卡设计概述并明确玩家目标
  2. 画入口、目标、路线和视线的平面草图
  3. 用基础几何搭建白盒并标记引导点
  4. 通过试玩检查节奏、迷路点和风险回报

动手练习

制作一个含教学区、变化区和挑战区的小关卡，先使用占位几何，不投入最终美术。

完成标准

试玩者不依赖口头提示能找到目标；记录迷路和失败位置；根据观察完成一轮白盒修改。

注意事项

教材以英文为主；不同游戏的移动能力和镜头会改变尺度，不要直接照搬其他项目的尺寸。

建议将实践步骤、使用版本与实际结果记录为学习笔记。以上练习均待实践。

策划与设计03 / 20

Twine 互动叙事

通过节点和链接制作互动故事，练习分支、条件与叙事反馈。

需要验证对话、任务分支或选择后果的设计。

阅读学习指南 ＋

建议学习顺序

  1. 从官网进入文档，选择并记录 story format
  2. 建立故事节点与分支链接
  3. 按所选格式学习变量和条件
  4. 设计选择的反馈与结局，并遍历路径

动手练习

制作一个有两次关键选择、至少两个结局的短故事，用状态变量记录一个选择后果。

完成标准

所有可达节点无意外断路；重开后状态正确；至少一次早期选择影响后续反馈；导出 HTML 可运行。

注意事项

Harlowe、SugarCube 等格式语法不同，不能混用；使用的素材和故事文本需要拥有相应权限。

建议将实践步骤、使用版本与实际结果记录为学习笔记。以上练习均待实践。

策划与设计04 / 20

Machinations 系统与数值设计

用资源流与系统图分析游戏经济，探索产出、消耗、反馈和增长。

正在设计货币、升级成本或资源循环。

阅读学习指南 ＋

建议学习顺序

  1. 明确每项资源的单位、产出和消耗
  2. 从官网文档学习节点与连接含义
  3. 搭建最小经济循环并定义假设参数
  4. 比较多组参数下的资源积累与瓶颈

动手练习

设计一个包含获取金币、购买升级、提升获取效率的循环，记录三组参数下的预期行为。

完成标准

说明输入、消耗与库存关系；指出是否存在无限增长或停滞；记录模型结果与实际试玩之间的差异。

注意事项

工具账号、方案限制与功能以官网为准；模拟结果依赖假设。数值表也能先验证简单模型，不必把工具作为前置门槛。

建议将实践步骤、使用版本与实际结果记录为学习笔记。以上练习均待实践。

策划与设计05 / 20

Game Accessibility Guidelines

按基础、中级与高级整理游戏可访问性建议，覆盖输入、视觉、听觉与认知需求。

需要设计可读、可操作的 UI、教程与反馈。

阅读学习指南 ＋

建议学习顺序

  1. 先读基础建议并挑选与项目相关的检查项
  2. 梳理输入映射、文字大小和颜色传达信息的方式
  3. 检查字幕、音量和关键反馈的替代形式
  4. 使用目标设备与具体任务做可用性检查

动手练习

为原型制作一页检查清单，落实可读文字、不只依赖颜色传递状态和可理解的操作提示。

完成标准

列出已落实和暂未落实的检查项；关键状态至少有清晰文字或图形提示；记录设备、输入方式与实际问题。

注意事项

这是一组设计建议，不代表合规认证；应结合目标玩家反馈，不要用健全用户模拟代替相关玩家的实际测试。

建议将实践步骤、使用版本与实际结果记录为学习笔记。以上练习均待实践。

GDC Vault 策划案例

查找开发者关于玩法、战斗、叙事和关卡设计的演讲与复盘。

希望分析成熟项目设计取舍，再形成自己的验证方案。

阅读学习指南 ＋

建议学习顺序

  1. 按设计主题检索演讲，并记录讲者和项目背景
  2. 区分演讲中的问题、约束、方案与结果
  3. 提取一个能用于自己项目的设计假设
  4. 做最小实验，记录与案例条件的不同

完成标准

笔记包含来源、背景、设计取舍与观察证据；不把个例当普遍结论；明确自己的实验成功标准。

注意事项

部分内容需要账号或付费权限；优先选择可公开访问的案例。演讲经验受团队规模、类型与发行背景限制。

引擎与编程07 / 20

Unity Manual

Unity 官方手册：场景、组件、物理、渲染与构建。注意选择与项目一致的编辑器版本。

准备使用 Unity 做 2D 或 3D 原型，具备基本 C# 语法。

阅读学习指南 ＋

建议学习顺序

  1. 编辑器界面、Scene 与 Game 视图。
  2. GameObject、Transform 与组件。
  3. Prefab 与场景管理。
  4. 输入、物理碰撞与 UI。
  5. 目标平台的构建流程。

动手练习

建立单场景收集原型：角色移动，触碰收集物后更新计数，完成后显示重开按钮。

完成标准

角色可以操作，收集物不会重复计数；重开后状态清零；目标平台构建可以启动。

注意事项

先记录编辑器版本。输入系统、渲染管线与包版本应与项目一致，不能直接混用不同版本教程。

建议将实践步骤、使用版本与实际结果记录为学习笔记。以上练习均待实践。

Godot Docs

Godot 中文官方文档，从第一个 2D 游戏到节点、信号与脚本。

希望从节点与脚本入门，制作轻量 2D 原型。

阅读学习指南 ＋

建议学习顺序

  1. 节点、场景与场景树。
  2. GDScript 基础与信号。
  3. 输入映射与角色移动。
  4. 碰撞层、遮罩与计时器。

动手练习

完成标准

障碍会生成；结束后停止计分；重开不残留旧障碍；导出版本可运行。

注意事项

确认文档与项目的主版本一致；Godot 3 与 4 的节点、API 存在差异。导出可能需要安装对应模板。

设计与架构11 / 20

Game Programming Patterns

在线阅读游戏编程模式，理解状态机、对象池、组件与事件队列。

已经写出一个小原型，开始遇到状态和模块耦合问题。

阅读学习指南 ＋

建议学习顺序

  1. 先阅读 Introduction 与 Architecture, Performance, and Games。
  2. State：表达角色或流程状态。
  3. Observer：拆分事件发送者和接收者。
  4. Object Pool：复用高频对象。
  5. Component 与 Event Queue：按实际需要继续。

动手练习

把原型中的待机、移动、受击改为显式状态；用事件更新 UI，避免 UI 直接管理角色状态。

完成标准

列出合法状态转换；重复受击、结束后输入等边界行为明确；改造前后玩法一致。

注意事项

先明确实际问题再引入模式。对象池需要重置状态，并不保证所有场景都更快；性能结论需要测量。

建议将实践步骤、使用版本与实际结果记录为学习笔记。以上练习均待实践。

音频与音效16 / 20

Freesound

搜索环境声与音效。每条声音需要单独确认许可及商业使用条件。

为交互、环境和反馈寻找声音素材。

阅读学习指南 ＋

建议学习顺序

  1. 用具体声音事件而非泛称搜索。
  2. 试听并检查长度、噪声和动态。
  3. 核对每条声音的许可。
  4. 保存作者、来源与许可。
  5. 剪辑后导入原型。

动手练习

为同一按钮准备悬停、点击与确认反馈，控制音量并测试快速重复触发。

完成标准

声音与动作对应；无明显削波；重复触发不过度叠加；每条音效都有来源和许可记录。

注意事项

CC 许可种类不同，含 NC 的授权不适合未经额外许可的商业用途。下载可能需要账号；访问与授权状态以原站为准。
